CAR RENTAL ("Rivano") - Documentation projet & Suivi Scrum

Auteur : Tom Mehl
Cours  : 3eme annee - Projet Rivano
Mise a jour : 25/09/2026 (rendu final)


1. OBJECTIF

	Une application de location de voitures de luxe : un catalogue de
	vehicules provenant d'une API REST et affiche dans une application Flutter
	conforme a la maquette Figma.


2. DEFINITION OF DONE (DoD)

A User Story is Done if :
  D1  le code compile sans erreur
  D2  l'API repond avec le bon code HTTP (200 / 400 / 404)
  D3  la route est documentee dans swagger.yaml et testable sur /docs
  D4  l'ecran Flutter gere les 3 etats : chargement / erreur / donnees
  D5  l'UI respecte la maquette Figma
  D6  le rendu est verifie sur emulateur Android
  D7  cette documentation est a jour

5. FONCTIONNEMENT DES FILTRES

  Tout passe par un seul etat : CarFilterState (car_filter_provider.dart).
  Il en existe deux exemplaires :
    - draftFilterProvider : ce que l'utilisateur est en train de regler
      dans la bottom sheet (le brouillon) ;
    - carFilterProvider   : les filtres reellement appliques a la liste.
  Le brouillon n'est recopie dans les filtres appliques que lorsqu'on
  presse "Show X Cars". Le compteur du bouton, lui, se met a jour en
  direct a partir du brouillon.

  filteredCarsProvider combine la liste de l'API, les filtres appliques
  et la barre de recherche ; l'ecran liste affiche uniquement ce resultat.

  Options desactivees : draftCarsIgnoringProvider(FilterFacet) recalcule
  le resultat en ignorant volontairement une facette (carType, price,
  seating ou fuel). Si plus aucune voiture ne reste pour une valeur
  donnee, le bouton correspondant est desactive.

  Filtre            Regle appliquee sur chaque voiture
  ----------------  ------------------------------------------------------
  Recherche         marque ou modele contient le texte
  Brands            marque exactement egale a la marque selectionnee
  Types of Cars     Luxury = tarif jour > 1000 CHF, Regular = le reste
                    (constante luxuryDailyPriceThreshold)
  Price range       tarif jour entre le min et le max du slider
  Rental Time       mode Day : exclut les voitures indisponibles sur la
                    plage de dates choisie (champ indisponibilites)
  Car location      ville ou canton contient le texte
  Rating            note moyenne >= note minimale
  Seating Capacity  nombre de places dans la selection
  Fuel Type         carburant dans la selection (essence = Petrol)
  Clear All         remet tous les filtres a zero


6. ARCHITECTURE

Flux : cars.json -> MongoDB -> API Express (port 3000) -> Flutter

DONNEES - doc/cars.json
  Tableau JSON de vehicules importe dans MongoDB, reference commune au
  serveur et au client. 20 champs par vehicule : champs simples (id,
  marque, modele, annee, categorie, statut, ...), objets (localisation,
  caracteristiques, tarifs, conditions, note) et tableaux (equipements,
  indisponibilites, photos).

SERVEUR - src/server (Node.js, 		Express 5, Mongoose, Swagger)
  app.js                       		demarrage + connexion MongoDB
  routes/carRoutes.js          		URLs de l'API
  controller/carController.js  		logique (validation ObjectId, 400/404)
  models/car.js                		schema Mongoose
  swagger.yaml + /docs         		documentation testable
  test/app.test.js             		9 tests Jest + supertest (BDD en memoire)
  Routes : 	GET /cars
			GET /cars/:id

CLIENT - src/client (Flutter, Riverpod, http, google_fonts, flutter_svg,
                     syncfusion, calendar_date_picker2)
  lib/src/features/car/
    domain/        modeles Dart 				(Car, Localisation, Caracteristiques,
                   Tarifs, Conditions, Note, Photo, Indisponibilite)
    data/remote/   CarService  					seul point d'appel a l'API + providers
    data/local/    fake_cars_repository 		(donnees de secours / dev, vide)
    presentation/cars_list/
                   car_list_screen.dart    		ecran liste (3 etats)
                   cars_results.dart       		grille de resultats + cas vide
                   car_card.dart           		carte d'un vehicule
                   brand_card.dart         		liste horizontale des marques
    presentation/car_details/
                   car_detail_screen.dart  		ecran detail (carrousel + infos)
    presentation/filter_bottomSheet/
                   filter_bottomSheet.dart 		panneau de filtres (bottom sheet)
                   car_filter_provider.dart		etat des filtres + liste filtree
                   type_cars_widget.dart   		filtre par categorie
                   price_range_widget.dart 		slider + histogramme des prix
                   rental_time_widget.dart 		Hour / Day + dates ou heures
                   custom_time_picker.dart 		selecteur d'heure
                   location_widget.dart    		filtre par lieu
                   stars_widget.dart       		note minimale (etoiles)
                   Siting_widget.dart      		nombre de places
                   fuel_widget.dart        		type de carburant
  constants/colors.dart, app_sizes.dart 		Chartre graphique

  Ecran de detail : la voiture est passee directement au constructeur
  (CarDetailScreen(car: car)), il n'y a pas de second appel a l'API.
  Les photos sont lues en asset local, avec repli sur l'URL puis sur une
  icone si le fichier est absent.

9. LIMITES CONNUES / DETTE TECHNIQUE

  - Rental Time en mode Hour : les heures sont choisies mais ne filtrent
    pas la liste. Seul le mode Day verifie les indisponibilites.
  - Le bouton "Book now" des cartes et le lien "View All" de l'accueil
    ne font rien pour l'instant.
  - Ecran de detail : consultation seule, aucune action de reservation.
  - Aucune gestion specifique des erreurs reseau cote client : si l'API
    ne repond pas, le message d'erreur brut est affiche.
  - Tests cote client limites aux modeles et aux providers : le rendu
    des ecrans n'est pas couvert automatiquement, il est verifie a la
    main sur emulateur.
  - Trois remarques de style restent dans flutter analyze (noms de
    fichiers filter_bottomSheet.dart et Siting_widget.dart).
