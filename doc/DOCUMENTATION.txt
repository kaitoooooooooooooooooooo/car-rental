1. CADRE SCRUM

OBJECTIF DE SPRINT
Livrer une application de location de voitures fonctionnelle de bout en
bout : catalogue de vehicules servi par une API REST et consomme par une
application Flutter conforme a la maquette Figma.


2. DEFINITION OF DONE (DoD)

Une User Story est "Done" si :
  D1  le code est sur main et compile sans erreur
  D2  l'API repond avec le bon code HTTP (200 / 400 / 404)
  D3  la route est documentee dans swagger.yaml et testable sur /docs
  D4  l'ecran Flutter gere les 3 etats : chargement / erreur / donnees
  D5  l'UI respecte la maquette Figma (couleurs, typo, disposition)
  D6  le rendu est verifie sur emulateur Android
  D7  la documentation (ce fichier) est a jour

4. CE QUI EST DEMONTRABLE AUJOURD'HUI (REVUE)

Scenario de demo :
  1. Lancer le serveur      -> npm start (port 3000)
  2. Ouvrir la doc API      -> http://localhost:3000/docs
  3. Tester GET /cars       -> liste JSON des vehicules
  4. Tester GET /cars/:id   -> un vehicule (+ 400 id invalide,
                               404 introuvable)
  5. Lancer les tests       -> npm test : 9 tests verts (Jest,
                               supertest, mongodb-memory-server)
  6. Lancer le client       -> flutter run
  7. L'application affiche le catalogue : logo Rivano, barre de
     recherche, une carte par vehicule avec photo, marque/modele et
     tarif, donnees venant reellement de l'API.

Chaine complete validee : cars.json -> MongoDB -> API Express -> Flutter.


5. ARCHITECTURE (RESUME)

Flux : cars.json -> MongoDB -> API Express (port 3000) -> Flutter

DONNEES - doc/cars.json
  Tableau JSON de vehicules, importe dans MongoDB, reference commune au
  serveur et au client. 20 champs par vehicule : champs simples (id,
  marque, modele, annee, categorie, statut, immatriculation, ...),
  objets (localisation, caracteristiques, tarifs, conditions, note),
  tableaux (equipements, indisponibilites, photos).
  Notation MongoDB : { "$oid": ... } et { "$date": ... }.

SERVEUR - src/server (Node.js, Express 5, Mongoose, Swagger)
  app.js                       demarrage + connexion MongoDB
  routes/carRoutes.js          URLs de l'API
  controller/carController.js  logique (validation ObjectId, 400/404)
  models/car.js                schema Mongoose
  swagger.yaml + /docs         documentation testable
  db.js                        connexion BDD reelle ou en memoire
                               (+ prepareDatabase pour les tests)
  test/app.test.js             9 tests Jest + supertest (npm test)
  Routes : GET /cars | GET /cars/:id

CLIENT - src/client (Flutter, Riverpod, http, google_fonts, flutter_svg)
  lib/src/features/car/
    domain/        modeles Dart (Car, Localisation, Caracteristiques,
                   Tarifs, Conditions, Note, Photo, Indisponibilite)
                   avec fromJson()
    data/remote/   CarService : seul point d'appel a l'API + providers
    data/local/    fake_cars_repository (donnees de secours / dev)
    presentation/  CarsListScreen + CarCard (3 etats : chargement,
                   erreur, donnees)
  constants/colors.dart, app_sizes.dart : charte issue de Figma
