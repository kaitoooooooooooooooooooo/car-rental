2. Navigation - app_router.dart

  C'est la liste des pages de l'app. 
  "/" c'est l'ecran principal avec les onglets, et
  "/car/:id" c'est la page d'une voiture (l'id dit laquelle).

    GoRoute(
      path: '/',
      name: AppRoute.home.name,
      builder: (context, state) => const AppShell(),
      routes: [
        GoRoute(
          path: 'car/:id',
          name: AppRoute.carDetail.name,
          builder: (context, state) {
            final carId = state.pathParameters['id']!;
            return CarDetailScreen(carId: carId);
          },
        ),
      ],
    ),

  Pour ouvrir la page d'une voiture on donne juste son id :

    context.goNamed(
      AppRoute.carDetail.name,
      pathParameters: {'id': car.id},
    );


3. API - GET /cars/featured (serveur)

  Le serveur renvoie les 10 voitures qui ont les meilleurs notes.
  Si deux voitures ont la meme note, celle avec le plus d'avis passe
  devant.

    exports.getFeaturedCars = (req, res, next) => {
      Car.find()
        .sort({ "note.moyenne": -1, "note.nombre": -1 })
        .limit(10)
        .then((cars) => res.status(200).json(cars))
        .catch(next);
    };

  Attention : /featured doit etre ecrit AVANT /:id. Sinon le serveur
  croit que le mot "featured" est l'id d'une voiture :

    router.get("/", carController.getCars);
    router.get("/featured", carController.getFeaturedCars);
    router.get("/:id", carController.getCarById);

9. Splash screen - splash/splash_screen.dart

  C'est le premier ecran qu'on voit quand on ouvre l'app. Le logo
  apparait doucement et grandit un peu. Pendant ce temps, l'app
  commence deja a charger les voitures, puis elle va sur Home.

  On utilise un ConsumerStatefulWidget parce que l'ecran doit se
  souvenir de son animation, et il doit aussi pouvoir lancer le
  chargment des voitures. SingleTickerProviderStateMixin sert a
  faire avancer l'animation image par image.

    class _SplashScreenState extends ConsumerState<SplashScreen>
        with SingleTickerProviderStateMixin {

  Une seule animation (fade, qui va de 0 a 1) fait les deux effets :
  le logo devient visible, et il passe de 90% a 100% de sa taille
  grace au Tween.

    late final Animation<double> fade = CurvedAnimation(
      parent: controller,
      curve: Curves.easeOut,
    );

    late final Animation<double> scale = Tween<double>(
      begin: 0.9,
      end: 1,
    ).animate(fade);

    FadeTransition(
      opacity: fade,
      child: ScaleTransition(scale: scale, child: ...),
    ),

  Quand on quitte l'ecran, on arrete l'animation pour pas qu'elle
  tourne pour rien :

    @override
    void dispose() {
      controller.dispose();
      super.dispose();
    }

    late final AnimationController controller = AnimationController(
      vsync: this,
      duration: const Duration(milliseconds: 900),
    )..forward();

    @override
    void initState() {
      super.initState();
      ref.read(featuredCarsListFutureProvider);
      Future.delayed(const Duration(milliseconds: 1800), () {
        splashShown = true;
        if (mounted) context.goNamed(AppRoute.home.name);
      });
    }

  Dans app_router.dart, le redirect force l'app a passer par le
  splash, meme si on recharge la page web sur une autre adresse :

    initialLocation: '/splash',
    redirect: (context, state) {
      if (!splashShown && state.matchedLocation != '/splash') return '/splash';
      return null;
    },


10. Localisation - GET /cars/:id/location (serveur)

  Pour mettre une voiture sur une carte, il faut sa position GPS.
  Nos voitures ont seulement une adresse. Donc le serveur envoie
  l'adresse a Google, et Google repond avec la position { lat, lng }.

    const apiKey = process.env.GOOGLE_MAPS_API_KEY;

    const { adresse, codePostal, ville, canton } = car.localisation;
    const address = `${adresse}, ${codePostal} ${ville}, ${canton}, Suisse`;
    const params = new URLSearchParams({ address: address, key: apiKey });

    fetch(`https://maps.googleapis.com/maps/api/geocode/json?${params}`)

  Fait en binome avec Simon Lauper. La cle API c'est comme un mot
  de passe pour utiliser Google : il faut pas l'ecrire dans le code
  et surtout pas la mettre sur GitHub ou tout le monde peut la voir.

  Donc la cle est rangee dans un fichier a part, src/server/.env,
  que git ignore (il est jamais envoye sur GitHub) :

    GOOGLE_MAPS_API_KEY=...

  Le serveur lit ce fichier au demarrage, dans app.js :

    const dotenv = require("dotenv");
    dotenv.config();

  Attention a l'ordre des routes : /:id/location doit etre mise
  apres /featured, comme expliquer pour la route 3.

13. Favoris - FavoritesNotifier (favorites/favorites_provider.dart)

  Meme idee que dans le projet Pokemon : on garde une liste des
  voitures aimees (un Set d'id). toggle ajoute la voiture si elle
  y est pas, et l'enleve si elle y est deja.

    class FavoritesNotifier extends Notifier<Set<String>> {
      @override
      Set<String> build() => {};

      void toggle(String carId) {
        if (state.contains(carId)) {
          state = {...state}..remove(carId);
        } else {
          state = {...state, carId};
        }
      }
    }

  Le coeur se redessine seulement quand CETTE voiture change, et
  pas a chaque fois qu'on touche une autre voiture, grace a select :

    final isFavorite = ref.watch(
      favoritesProvider.select((favs) => favs.contains(carId)),
    );


14. Voitures en favori - favoriteCarsProvider

  Ce provider prend deux choses : la liste des favoris et la liste
  de toutes les voitures. Il garde seulement les voitures qui sont
  dans les favoris.

    final favoriteCarsProvider = Provider<AsyncValue<List<Car>>>((ref) {
      final favorites = ref.watch(favoritesProvider);
      final carsValue = ref.watch(carsListFutureProvider);
      return carsValue.whenData(
        (cars) => cars.where((car) => favorites.contains(car.id)).toList(),
      );
    });

  FavoriteCarsSection (dans profile/) affiche le resultat. Si y a
  aucun favori, on affiche un petit message. Sinon on affiche les
  voitures cote a cote, et un clic ouvre la page de la voiture.

25. ValueChanged - option_chips.dart / stars_widget.dart

  ValueChanged c'est une fonction qu'on donne au widget, et le widget
  l'appelle avec la valeur choisie (par ex. "Electric"). Le widget
  lui sait pas quoi en faire, c'est l'ecran au dessus qui decide.
  Comme ca on peut reutiliser le meme widget pour differents filtres.

    final ValueChanged<String> onTap;

    onTap: isAvailable ? () => onTap(option) : null,

  Exemple avec le filtre carburant : on donne directement la
  fonction qui ajoute ou enleve le carburant.

    OptionChips(
      title: 'Fuel Type',
      options: options,
      selected: selected,
      onTap: notifier.toggleFuel,
    ),

  Les etoiles marchent pareil, mais avec un nombre (la note) :

    final ValueChanged<double> onRatingChanged;

    onTap: () => onRatingChanged(starValue),
